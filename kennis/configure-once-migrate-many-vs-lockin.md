# Don't start from scratch every OS update: vendor-neutral workspace layer

Bas's 2018 stance, framed around the maxim "standing still is going backward." He argues IT can no longer postpone OS upgrades indefinitely (unsupported workspaces are inevitable otherwise) and that more workloads are unavoidably getting "cloudified" ("and why should you [ignore it]?"). His prescription is a workspace layer that is a one-time purchase and one-time configuration, so that the user's settings and data follow them across device, OS version, on-prem or cloud without reconfiguring or re-migrating each time. The thing he most values about the Liquidware approach is freedom of choice and no vendor lock-in: users can sit on-prem or on DaaS and be moved back and forth, "the workspace will simply follow the user." This is openly vendor-advocacy content (he was working with/around Liquidware at the time) but the underlying conviction (avoid platform lock-in, decouple the user environment, never start from scratch on each Microsoft OS release) is a consistent thread in his thinking.
