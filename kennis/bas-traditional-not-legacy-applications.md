# Bas's reframe: call them 'traditional' applications, not 'Legacy'

Bas describes combining delivery models in practice: accessing a published desktop via DaaS (Microsoft Azure Virtual Desktop / AVD being one of the most-used technologies) to reach one of the millions of Windows applications still in use today, frequently combined with various SaaS software accessible through a browser.

Years ago Bas followed an HBO Masterclass module on Cloud computing; his final paper, title "Cloud only? Nee. Cloud first of Hybride? Ja!", is included at the end of the book (though he notes he thinks somewhat differently today - times change). Researching still-in-use Windows applications, often branded 'Legacy', he found there were literally tens of millions - a key reason virtualised Windows desktop environments will exist for many years. New Windows applications are even still being created today.

His characteristic reframe: he argues we should call them 'traditional' applications, not 'Legacy', because Legacy refers to something outdated and barely used - which is absolutely not the case here. Modern options to replace these traditional apps do exist, but it is far from simple: easily several weeks, even months per application, plus the cost question - who does it, their hourly rate, is success guaranteed, can data be reused, what changes for users. In short, Windows applications will be with us for many years. He cites community friend Shawn Bass (CTO at Citrix at the time): "After a nuclear war the only things left will be cockroaches and Windows applications."

Definition of a Windows application: software installed on the Windows OS that interacts directly with its core components, using the Windows API to access system resources (file system, networking, memory management, hardware). On install it creates system files and registry keys to function - so the connectedness to the OS is large.
