# Bas's low-effort capability build: KISS, low-threshold, broadly carried

When Bas designs how a team ramps up on a new technology, he sets deliberate constraints up front so the build stays light and repeatable instead of turning into a months-long certification marathon. His starting principles:

- **Keep It Stupid Simple.** Don't over-engineer the enablement.
- **Don't sink months into it.** Certifications are the explicit exception, not the default path. Get hands-on first.
- **Low-threshold and repeatable.** The ramp-up has to be something the team can run again for the next person and the next technology, not a one-off heroic effort.
- **Knowledge must be carried broadly.** Aim for the capability to live across the team, not in one specialist's head — depth can come later. The first pass deliberately does not need to be deep ('in eerste instantie niet diepgaand').
- **Start with the low-hanging fruit.** Pick the part of the new stack that is genuinely easy to stand up first, get an own environment live, and run the first workshops early so people learn by doing.

The reusable point: Bas treats 'breadth and momentum now, depth later' as a feature of the plan, not a compromise. A vendor management/automation layer on top of the platform is exactly the kind of low-hanging fruit he points teams at, because it lets a small team carry the capability without deep platform mastery on day one.
