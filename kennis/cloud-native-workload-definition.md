# What 'cloud native' actually means

Working definition used to separate genuine cloud-native platforms from rebadged legacy:

Cloud-native workloads are based on a distributed (loosely coupled) and continuous integration and delivery model. They are not machine- or OS-dependent (they operate at a higher abstraction level), are API-driven, consist of lightweight code, and are extremely scalable.

Think microservices, container technology, serverless, Infrastructure as Code, and the various PaaS platforms.

Used as a litmus test when comparing EUC/DaaS vendors: classic VDI/RDSH that merely runs in a cloud VM is **not** cloud native; 'SaaS-ifying' legacy is a marketing move, not an architecture.
