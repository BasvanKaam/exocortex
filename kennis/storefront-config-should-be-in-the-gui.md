# StoreFront's powerful features shouldn't be locked behind web.config

Bas's 2014 critique: he loves that StoreFront adds an extra layer of HA/DR, but dislikes that it is only configurable in the web.config file. 'Why not build this functionality into the GUI instead? Is what I'm thinking.' His user-empathy argument: die-hard techies will do it over breakfast, but the average admin would prefer something visual and won't want to spend hours in E-docs backing up config files. He cites a real case where a major Citrix consultancy declined to implement StoreFront multi-site because it would 'only complicate the overall configuration / architecture' (also tied to hand-over concerns). He fairly airs the counterpoint from Esther Barthel: doing it by hand means you learn exactly what's going on under the hood. An early, durable example of his usability-first, design-empathy stance toward Citrix tooling.
