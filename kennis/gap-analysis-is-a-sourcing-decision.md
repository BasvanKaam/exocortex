# A cloud GAP analysis must end in a sourcing decision, not just a skills delta

In the SCAF GAP-analysis worksheet, Bas structures the gap between target (SOLL) and current (IST) state so that every competency is forced into one of five dispositions: keep in-house, train, declare not needed, outsource, or other. The stance embedded in this design is that identifying a knowledge gap is not the deliverable; deciding what to do about each gap is. By baking the sourcing choice into the same row as the gap, the worksheet refuses the common failure mode where an organization lists everything it lacks and then defaults to training or hiring across the board. Some capabilities (e.g. the hypervisor layer in his example) should be dropped because they no longer apply in a cloud-native model, and others (e.g. AVD/Cloud PC, SLAs/DAPs) are deliberately outsourced rather than built. The position: scope your own competency deliberately, do not try to own everything.
