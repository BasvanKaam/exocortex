# Combined PDCA/DMAIC cycle and lessons-learned in SCAF Adoption

The Adoption phase runs on a simplified combination of a PDCA (Plan-Do-Check-Act) and a DMAIC cycle. The stated reason: using cloud services generally demands a different way of working and thinking, so there must be enough attention for cultural shifts toward a more iterative (agile) way of working. You can keep working the 'old' way and it will work, but you will not extract the maximum return from cloud services that way.

A running 'Lessons learned' document is kept during both Execution and Adoption: by applying this approach to the first migrations you learn a lot fast, to benefit from later. The continuous question is whether what you are doing is still the right thing and how it could be done differently or better - then act on it. Concretely: don't run repeating tasks by hand (automate), prevent unused or under-utilised resources from running (unnecessary cost), and keep the latest versions of products/services in use (security and functionality). The ultimate goal is always to retire, replace or improve services at the right moment and in the right way.
