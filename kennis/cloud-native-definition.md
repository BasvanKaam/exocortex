# Cloud-Native: Designed for the Cloud from the Start

In its simplest form, Cloud-native means software is designed and built from the very beginning to make optimal use of everything the Cloud offers. Unlike traditional software that runs on specific servers or hardware, Cloud-native software is more flexible, scalable and efficient (but also more complex to set up and maintain).

A more technical definition: Cloud-native workloads are based on a distributed (loosely coupled) and continuous integration/delivery model. They are not machine- or OS-dependent (they operate at a higher abstraction level), are API-driven, consist of lightweight code, and are extremely scalable.

Examples include microservices, serverless, container technology and various PaaS platforms. None of these technologies have anything to do with IaaS (Infrastructure as a Service), although it may look similar; the most obvious IaaS example is a virtual machine. Creating a VM could, however, be an *outcome* of deploying IaC.

Key benefits the book lists: no dependency on specific infrastructure (workloads move easily between public/private/hybrid); faster and safer updates via CI/CD without downtime; better efficiency and lower cost via serverless/PaaS; high availability and fault tolerance from loosely coupled microservices/containers; and fast automation/repeatability through IaC (Terraform, Azure Bicep).
