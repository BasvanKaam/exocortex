# Bas's ADDIE course-planning method

The intake template I run before building any Nerdio learning module. ADDIE, but with one twist: I rename the final phase from "Evaluate" to **Examine**, so the five phases are Analyze, Design, Develop, Implement, Examine.

## Analyze (the heaviest phase up front)
- **Parent Goal**: one paragraph stating the capability the module unlocks, and why it matters now. I deliberately anchor to a "critical and hot topic" so the module earns attention (e.g. Zero Trust).
- **Audience**: name the roles explicitly (IT admins, system engineers, cloud architects, technical leads).
- **Outcomes ("By the end, learners will be able to...")**: 3-5 capability statements, action verbs, measurable.
- **Subsidiary objectives / core concepts**: the concrete sub-skills that ladder up to the outcomes.

## Design
- **Assets to create**: video tutorials, slide deck, graphics/overviews, knowledge-check quizzes + a final assessment.
- **Delivery vehicles, phased**: start with self-paced video modules on the learning portal; later hands-on labs with real-world scenarios; optionally click-through simulations and drag-and-drop interactions "once we get to that point."
- **Reviewers**: pull in Product, a TAM, and Training & Development so the content is verified from three angles before launch.
- **Success metrics**: completion rate, knowledge-check/assessment scores, learner feedback on clarity and relevance, and a post-training evaluation that measures whether learners can apply the concepts.

## Develop
Link the production tracker (Asana / DevOps / spreadsheet). Keep planning and production state in one place.

## Implement
- **Launch**: internal comms + the Nerdio online community, publish on the portal with email notification to the target audience.
- **Check-in cadence**: weekly for the first 2-4 weeks (issue-driven), monthly review cycles to fold in feedback, quarterly updates to track product enhancements.

## Examine
Three standing questions every revision: what is working well, what isn't, what needs to change. Plus a forward-looking "to-do in next version" and a versioned changelog. The module is never done; it tracks the product.

The template is itself versioned (v1.0) and carries a changelog field, so each course is a living document, not a one-off deliverable.
