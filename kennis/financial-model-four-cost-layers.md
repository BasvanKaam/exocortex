# Four-layer segmentation of the cloud cost model

> Referentie uit het Weolcan Cloud Governance Framework (WCGF). Niet Bas zijn eigen IP, hier bewaard als naslag.

To keep the financial model clear, the framework consolidates costs into layers and zooms in only when necessary. The required level of detail depends on the purpose of the analysis: infrastructure-oriented organizations may need to dig down to storage and memory capacity to compare apples with apples across cloud models, whereas a SaaS-uptake strategy makes that depth excessive and shifts attention to technical application management and software development costs.

The four layers to consolidate the data into:
1. Infrastructure (including management).
2. Software (purchasing licenses and maintenance).
3. Application, middleware and database management (both technical and functional management).
4. Software development (customization, extensions, maintenance, etc.).

Layering lets you distinguish, for example, the Linux platform from the Oracle platform, or high-performance storage from archive storage.
