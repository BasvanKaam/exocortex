# Compare cloud to cloud, not cloud to on-prem

A framing position I apply when assessing and pitching a cloud workplace.

## The position
When you evaluate a cloud workplace, **compare it against the cloud variant of the incumbent, not against the on-prem setup.** Take the incumbent's own cloud story and substitute the new solution into it. Comparing a cloud service to an aging on-prem deployment flatters the cloud option for the wrong reasons and sets wrong expectations. Like-for-like keeps the assessment honest.

## Why I hold it
- A cloud-to-on-prem comparison wins on points that are really about old hardware, not about the solution. That's a hollow win that comes back to bite you in delivery.
- The genuinely shared challenges (end-user clients, connectivity, security, image maintenance, migration work) are the same in either cloud world. Comparing cloud-to-cloud surfaces them honestly instead of hiding them behind "but it's not on-prem anymore".
- It keeps me honest about misfit. Some incumbent capabilities (deep network optimisation, specific policies) genuinely don't have an equivalent yet. A like-for-like comparison forces that to the surface in pre-sales.

## Corollaries I apply
- **Treat the new platform as just another migration.** Inventory, migrate, validate. Same discipline as any cloud migration, no magic.
- **Name what doesn't fit.** "Everything except very heavy graphics, and always test first." Honesty about the edge cases is part of the pitch, not a weakness in it.
- **Avoid vendor lock-in as a selling point**, but don't pretend the trade-offs (a younger product, ongoing development) don't exist; flag them.
