# Key Takeaways - cloud exit strategy (Chapter 12)

Bas's summary: a cloud exit strategy is a practical and necessary part of a cloud strategy, providing a plan for when switching to another solution is needed due to changing costs, compliance demands or service quality. Thinking about a possible exit at the very start keeps an organisation flexible - reinforcing his principle that 'the exit comes before the onboarding'.

Core points:
- Vendor lock-in is a common risk because providers use specific technologies and standards; a worked-out exit strategy limits dependence on a single vendor.
- Compliance: new regulation may require data in a specific region; if a provider no longer complies, an exit strategy makes it easier to find an alternative and avoid legal risk.
- Provider quality is not static (performance, reliability, customer service change over time); the cloud model - IaaS, PaaS or SaaS - matters, with IaaS easier to migrate and SaaS/cloud-native more complex.
- An exit strategy needs a clear plan: timeline, data-migration action plan, and a mechanism determining when an exit is needed, plus SLA analysis.
- A complete inventory and documentation of cloud components (data, applications, networks, dependencies) enables a smooth migration.
- The plan must address data integrity and security (e.g. encryption, testing export tools) and describe how data is fully deleted from the cloud, including proof.
