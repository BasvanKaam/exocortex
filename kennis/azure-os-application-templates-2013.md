# Azure forced Microsoft's OS and application templates (2013)

How it worked then: within Azure you had to use Microsoft's OS and application templates when setting up VMs, so you could not install or configure every server role and feature you were used to on-premises. Installing Hyper-V inside an Azure VM, for example, would not work. OSes and applications used in Azure also had to include License Mobility and Software Assurance. The recommended hybrid pattern was to run client VDI on-premises in your own datacenter and host the Hosted Shared Desktops in Azure.
