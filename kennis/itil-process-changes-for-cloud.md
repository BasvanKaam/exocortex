# ITIL Processes That Need Attention When Introducing Cloud

Bas argues the transition to cloud is the ideal moment to re-evaluate or (re)introduce ITIL. He provides a table of ITIL processes that, at minimum, deserve attention when introducing cloud services, organised by focus area:

- **Strategic — Financial management:** new Opex chargeback models; flexible (re)charging and settlement.
- **Design — Service catalogue management:** a portfolio of standardised services; define clear functional descriptions together with enterprise-architecture (EA) architects.
- **Design — Service level management:** define SLAs per service, per department (customer).
- **Design — Capacity management:** create a forecast model that accounts for the characteristics of cloud services.
- **Transition — Change management:** adapt based on new responsibilities; automate as much as possible to support cloud's dynamic nature.
- **Transition — Asset & config management:** automate, because cloud services can bring a high rate of change.
- **Operation — Event & incident management:** connect the service desk to the cloud provider(s)' own incident management process.
- **Operation — Request fulfilment:** aim for a self-service portal to offload the service desk.

Bas is candid that ITIL's added value can be hard to make visible for routine matters like ticket creation, but it strengthens operational frameworks and creates structure, and can be enriched with self-service.
