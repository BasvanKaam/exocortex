# Bas's ADDIE method for Nerdio course design

His reusable instructional-design template, captured from the Azure Local module. He runs ADDIE as Analyze, Design, Develop, Implement, Examine (note: he uses 'Examine' for the final E rather than the classic 'Evaluate'). Each phase answers a fixed set of questions.

**Analyze** - the planning core:
- Parent Goal: one paragraph stating what the training equips learners to do and how it differs from the unmanaged/native baseline (he always contrasts 'the Nerdio way' against multi-portal, manual scripting).
- Audience: name the concrete roles (partners/customers, IT admins, cloud engineers/architects, sales engineers, security/compliance).
- Terminal objectives: a 'by the end, learners will be able to...' list of understand/explain/create/configure/manage verbs.
- Subsidiary objectives / core concepts: the granular skills under each terminal objective.
- Assets to create, delivery vehicles (LMS / Nerdio Learning Portal self-paced), reviewers (TAMs, PMs, senior engineers), and success metrics (completion rates, quiz/assessment scores, learner feedback on clarity/accuracy/relevance).

**Design** - define the core flow: an ordered module sequence from overview/architecture through setup, provisioning, configuration, lifecycle, monitoring, to advanced ops/labs.

**Develop** - enumerate the concrete assets: text modules (step-by-step with screenshots and links to official docs), optional short video tutorials, knowledge-check quizzes after each major section, and a scenario-based final assessment. Link the production tracker (Asana/DevOps/spreadsheet).

**Implement** - launch plan: how to announce (partner comms, internal MSP channels, email to admins/SEs/partners), where to publish, and a check-in cadence (weekly for the first 2-4 weeks, then quarterly).

**Examine** - the review loop: what's working, what isn't, what changes are needed, a to-do for the next version, and a versioned changelog.

Recurring design signatures: pair every product capability with a knowledge check; always include a culminating scenario-based assessment ('design a complete deployment'); build a changelog and a next-version to-do into the course itself so content stays current with product releases.
