# In a hybrid world, app virtualization beats desktop virtualization

Bas's stance, written as a draft (with a colleague flagging it as a 'heftige uitspraak' and asking him to nuance it). His argument: application virtualization (and it doesn't even have to be true virtualization) is the best-suited technique to give users a SaaS-like experience when consuming traditional Windows applications, especially when a portal/workspace aggregation hides where each app and dataset is launched from. What matters is only how the user experiences it; how it is actually delivered doesn't interest them.

The sharp part: he argues desktop virtualization has little place in a hybrid world. Users don't want a virtual workplace in the cloud or a datacenter; they want the apps they need to launch easily on the physical endpoint they already have. He acknowledges reasons to still choose desktop virtualization exist, and after pushback he nuances it to 'choose what fits best given the client's technical possibilities/constraints, requirements and wishes' - and he can imagine cases where the new Windows Virtual Desktop fits well, for reasons beyond just the desktop: Office 365 integration/optimization (unavoidable) and extended Windows 7 support among them.

This is a notably strong, contrarian EUC position that the brain otherwise only holds in softer forms.
