# Training content must be technically true and honestly named

Bas's stance, evident throughout his NME-201 review: instructional content is only as good as its technical accuracy. He will not let a misleading module name, an oversimplified benefit list, an incorrect 'correct' exam answer, a duplicate answer option, or a knowledge-check that tests untaught material slide. Two specific positions he argues:

- Don't keep weak content for completeness. If an intro overview adds little, cut it and start with the stronger core-value module.
- Name things for what they actually are. A 'prerequisites' module that mostly covers permissions applied during installation should be renamed to reflect that it is about (API) permissions, because the wrong label misleads learners about what must be in place beforehand.

Underlying belief: training should be anchored in real deployment experience (the friction the field actually hits, like permissions and security hardening) and every question must be verified against the truth before it ships.
